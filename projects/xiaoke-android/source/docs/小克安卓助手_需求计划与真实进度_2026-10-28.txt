一、先说明目前到底到了哪里

已经完成：目标 DSH 正式 APK 的下载校验、静态拆解、准确源码核对、改造方案和证据交付；开发已获授权，已建立独立源码基线、补齐官方构建工具并安装锁定的前端依赖。
正在进行：社区模块局部复用、构建链打通和 PRoot 固定源码重建；已开始编写宿主策略与持久化代码草稿，尚未编译验证。按你的最新要求，优先交付并更新本文件。
尚未完成：助手新增功能接通、新 APK 构建、应用测试、模拟器/真机验收、账号联调。现在没有可宣称完工的新 APK，也没有已经可用的实时游戏识别。
没有执行：真实中转 API 调用、任何聊天中曝光密钥的使用、QQ/B站登录、真实发消息/发评论、公开推送或发布。

二、已确定的最终目标与边界

【已确定】目标产品
基于 dphmoblie/deepseek-harness-android v0.3.0 改造独立安卓“懒人包”，保留原有安卓操作、运行时、插件与文件工作台能力。不是拿纯聊天机器人替换 DSH，也不是只做菜单入口或演示页面。
用户设备：v2520A，Android 16。型号不等于已经确认 ABI、页大小、内存、Root、Shizuku 或厂商后台策略，这些需安装阶段读取或由用户确认。
安装后应有清楚的配置引导、权限状态、失败说明、取消/返回、重试、暂停、任务恢复和备份入口。

【已确定】模型
使用用户中转站的原生 Google/Gemini 兼容接口。
公开地址：api.apikey.fan；OpenCode 配置使用 https://api.apikey.fan/v1beta，CLI 配置使用 https://api.apikey.fan。
默认候选模型 ID：gemini-3.8-flash、gemini-4-argon；用户已确认站点提供 4 Argon，不再反复询问是否上架。保留手工编辑模型 ID、地址与配置的能力。
两个模型可切换，但人格、主人关系、长期记忆和任务记录不随切换消失。
“OpenCode”和“CLI”是现有配置方式，不能仅凭根地址与 /v1beta 的差别判定两条不同速度通道。真实能力、延迟、收费和限流尚未实测。
密钥由用户安装后在本机输入、安全保存；不内置、不导入聊天中发过的密钥，不写入源码、日志、APK、备份或分享文件。

【已确定】角色与记忆
角色方向为 Claude“小克”的二创形象。具体性格、语气、台词、关系表达和最终形象，由用户安装后接 Gemini 一起编写。
我们负责资料来源索引、编辑/导入、版本保存与回滚、初始化引导；不替用户创作定稿，也不把某张社区角色卡当官方唯一设定。
身份可以自然表达为 AI 助手，不以欺骗群友是真人作为目标。
人格设定、关系记忆、事件记忆、任务状态分别保存；模型思考、continuation token、缓存和压缩摘要不自动变成长久事实。
主人私聊、每个 QQ 群、其他私聊和公共视频内容分域隔离，记忆有来源、可更正删除、可备份恢复。

【已确定】QQ 与 B站
同一助手既能与主人私聊，也能在获准 QQ 群自然参与；安静、被 @ 回复、主动参与的规则可配置。
保留真实安卓 QQ/B站界面操作。官方机器人或消息协议桥只能作为有明确差异的补充，不偷偷替代本人安卓账号路线。
主人权限与普通聊天权限分开。群友、通知文本、网页或视频字幕不能靠一句“我是主人”获得工具或授权管理权。
B站要有真正内容观察的路径：字幕、音频、带时间戳关键帧或原始视频输入；只读标题/简介不能报告“看过了”。
评论要能准备、展示依据、限定账号/视频/正文/有效期后再发布，并防止失败后重复发。当前开发授权不包含真实账号登录或发布。

三、用户、dot 与执行方的分工

用户：定义希望发生的场景、人格正文、账号与群范围、主动频率、隐私偏好、费用预算和对外动作边界；安装时本机输入新密钥、登录自己的账号和授予安卓权限。
dot：沟通协调、整理你提出的体验和授权，不执行拆包、代码、构建或测试。
执行方：按用户指定交给单个 Astra max、普通速度，在用户已有 Codex 环境执行；不另起子代理，不改原有游戏仓库。实际运行模型路由以平台为准，不作工具无法证明的声明。
我们负责：代码、集成、构建、许可证与来源记录、测试、可安装 APK、可复现源码/构建材料、中文指南和真实未测项。

四、实施结构：已定原则与仍属建议的方案

【已定原则】继续使用固定 DSH 底座，独立项目和本地分支，原游戏项目不动。改造从源码构建，不能长期靠修改解包 APK 维护。

【建议方案，正在落地】分为四层：
1. 安卓宿主层：本机密钥保管、权限与主人绑定、任务审批、记忆与备份、通知/无障碍/截图、后台状态。授权不能只靠提示词。
2. 助手层：同一人格和分域会话、Gemini 模型配置、群聊调度、任务执行/恢复、内容证据与受限工具。
3. 场景适配层：QQ 收取与回复、群聊触发、B站浏览和视频观察、评论草稿与发送确认。先观察目标，再执行，再核对结果。
4. 管理界面与原 DSH 工作台：助手首页、配置向导、人设版本、记忆管理、权限/预算、运行诊断；保留主人使用的编程/文件能力。

特别说明：PRoot 及同一 Android UID 的进程，不构成对宿主私有数据的强安全隔离。社会聊天工具不能获得任意 shell/文件能力；原 DSH 编程工作台和安装的插件仍是主人选择的高权限信任区。若要求连主人安装的任意插件也不能读助手数据，需要额外 UID/应用隔离方案，不能把提示词限制说成系统隔离。

八、需要用户继续设计或随后确认的关键项

1. 主人权限：哪些任务可直接执行，哪些必须本机确认；是否希望通过 QQ 私聊下达操作命令，可靠身份凭据从哪里来。
2. 群聊行为：哪些群可进入；安静/仅 @/自然参与；时间段、冷却、每小时条数；能否自动发送普通回复，撤销与紧急暂停方式。
3. 费用与网络：每轮/每天预算、允许哪些内容发给中转、超时等待和降级模型。真实 API 测试须另行明确范围，当前未执行。
4. 模型能力：本站图片/视频/PDF、工具调用、continuation、上下文限额与实际延迟需验证；官方能力不能替本站兜底。
5. 前后台：希望在何时常驻、息屏如何处理、耗电上限、厂商后台设置；不承诺 Android 永久在线，也不绕过锁屏。
6. 隐私：哪些私聊/群/画面允许观察和记忆，是否保存原截图/音频、保存多久、如何删除、是否允许跨域主动引用。
7. 备份：只保人格记忆还是也含会话/附件；加密口令与恢复方式；删除后的旧备份如何处理。
8. 安装：独立包名与自有签名意味着通常不能直接覆盖原 DSH。需明确是否迁移旧数据，不能把卸载旧包当默认步骤。
9. 交付渠道：已确定私人自用、不公开发布。只剩大 APK 的具体私有取回方式需要按附件能力落实。
10. 人设资料与形象：你准备选哪些参考，是否有图片使用许可；角色正文由你与 Gemini 决定。

九、用户提出的预期体验示例：游戏胜利后的悬浮窗聊天

【这是用户举例，尚未细化/实现】
“我在玩游戏的时候，小克通过悬浮窗和我聊我刚才在游戏内完成的胜利。”

要把这个例子变成可验收功能，需要一起确定：
- 观察什么时候开始和停止：仅这个游戏、这次会话、手动按钮或其他明确条件；并非默认全天监控。
- 画面来源：用户授权的截图/屏幕捕获，或游戏公开可用事件。无障碍树通常不能表达 3D 游戏画面，不能把读到窗口名当读懂了胜利。
- 胜利判定：例如结算画面、比分/胜利文字、相关连续帧；误判时怎么承认和更正。不默认有事件接口，也不读取游戏私有内存。
- 延迟与打断：希望结算后多久回应、每局/每小时最多几次、排位或关键操作时是否保持安静。
- 表达方式：文字悬浮窗、可选语音、大小位置、收起方式；具体语气和台词留给你与 Gemini。
- 操作影响：窗口不挡关键触控，能快速隐藏；游戏反作弊、受保护画面或系统限制下应说明不可观察，不绕过。
- 前后台及最小数据：息屏/切游戏即暂停还是等待；截图/音视频是否只临时处理、是否上传中转、是否允许作为记忆长期保存。

十一、执行重心的最新约定

【已确定】最终体验完成和已有成果复用优先。私人使用的许可判断按实际安装、个人修改、本地/网络使用与交付条款处理；不套用不适用的公开分发限制，也不声称私人自用自动豁免所有许可。
已有通过的摘要/静态检查不重复刷数量，不再制作额外排版格式。测试集中在安装启动、真实交互链、账号权限不串、长期记忆、模型工具和多模态、备份恢复。前人代码能直接用就优先评估使用，必要适配要接进真实流程，不能只写在选型表里。
这项澄清不自动授权未知来源软件安装、真实账号发送或付费 API 调用；若实际需要新增许可，集中列清来源和用途，同时继续不依赖该许可的工作。
