# 回复延迟

Gemini 请求始终使用原生 SSE。客户端复用连接，首段正文立即回调；后续片段最多每 400ms 回调。收到完整结束事件后收尾，若 usage 单独随后返回，最多再等 200ms。失败、续传和每次尝试仍走原有计费、取消与降级路径。

聊天不再先发联网能力探测。未知能力先提供查询工具，真正查询时再确认支持情况；关闭联网查询或已确认不支持时不提供。内置网页工具仍只在独立研究请求中使用。

本机主人的明确查询、看屏幕、后台任务请求可以先收到一句短回应。它只是确认意图，工具结果仍以真实执行回执为准。群聊没有这条提前外发路径。短回应和流式正文写入任务后，后端通过已有 `moduleState` 通知刷新，不等待下一次轮询。

独立的短寒暄、天气、疲惫或心情陈述，且最近三条用户消息也没有任务线索时，第一轮省略工具声明。附件、疑问、旧话题指代、代码和不确定表达保留全量工具；追问合并及后续工具轮恢复。简单闲聊的 medium/high 思考调为 low，原本为 low 时不变。人设全文不改。

隐私范围、来源有效性检查、待审与急停执行路径保持。工具仍按顺序执行：部分工具持有来源校验事务，网页研究也共享可取消的模型客户端，不能直接套线程池。

## 生产计时

聊天任务保存 `task.latency`；后台模块的 completed/failed/cancelled 事件携带 `latency`。计时使用单调时钟，只有阶段、工具名、数值和结果状态，不保存提示词、参数或回复。

| 字段 | 含义 |
|---|---|
| queueMs | 从提交到模型工作队列开始处理 |
| preparationMs | 开始处理到准备好模型输入 |
| memoryRecallMs | 自动记忆检索，包含可能的向量请求 |
| promptAssemblyMs | 提示词、历史与角色卡字段组装 |
| toolSchemaMs | 工具声明组装累计时间 |
| estimatedPromptTokens | 本地输入估算，包含工具声明；不是服务端精确 token 数 |
| acknowledgementMs | 首次本机短回应写入任务 |
| firstVisibleTextMs | 首次可交付文本，可来自短回应或模型 |
| firstModelTextMs | 首次模型正文写入任务，排除短回应和 thought |
| elapsedMs | 本轮总耗时 |
| requests | 每次请求的 headers、首事件、首思考、首正文、usage、结束、完整耗时及服务端 token 用量 |
| tools | 每次实际工具执行的耗时与是否成功 |

`memoryRecallMs` 和 `promptAssemblyMs` 属于 `preparationMs`，不能再次相加。请求计时从计费/取消守卫通过后开始；服务端未报告的 usage 保持缺失，不填零。网页工具内部请求与主对话请求分别记录。

## 复跑

见 [延迟基准说明](../source/android/app/src/test/latency-bench/README.md)。基准编译冻结的生产提示词和客户端，使用环境变量中的私有人设与中转配置，结果固定保存到已忽略的 `latency-output/`。

云中转配对测量、真实网页查询、本地工具 fixture、受控 TLS 和通知交付测量分开报告。JVM 基准不等于真机显示时间，也不包含 QQ 收件端或手机工具执行时间。
