# rustnight/ 交接说明（分支 `ccr-90bdeb0b-ndb9mf`）

这是**另一个账号的会话**在 2026-11-11 上午做的同一个需求的早期版本，做到 HUD 时中断，当时没推送。
现在原样存档。**项目的主交接文档是 `ccr-288ba2a4-9j5wy5` 分支根目录的 `HANDOFF.md`，以那一份为准。**

## 先说结论

- 这个目录**从来没有在引擎里跑起来过**，现在也启动不了（原因见下）。所有脚本都是"写完但没运行过"的状态。
- 它按的是**旧方向**：GL Compatibility 渲染器、240p 低分辨率 + 抖动滤镜、兼顾手机网页。
  用户后来定的方向是 PC / Forward+ / 现代光照 / 不用复古滤镜（见主交接文档第 3 节），所以这里的画面方案已经作废。
- 建议把它当作**可以拆零件的参考实现**，不要当成要继续开发的项目，也不要整体合并进 `fps/`。

## 哪些设计值得搬到 `fps/`（按价值排序）

这些是逻辑和数据，不依赖旧的画面方案。搬的时候要按 `fps/` 的接口改写（`take_hit(damage, point, dir, weapon_data)`、
`Player.noise_made(radius)`、命中盒层等），并且**都要重新验证**。

1. **丧尸群体生态** `zombie_manager.gd`：只有玩家附近的丧尸是节点，其余是轻量记录，仍会游荡、被噪音吸引迁徙、
   每小时从地图边缘补充、随天数增长。对应主文档 6.3 的"丧尸和噪音"，但多了"虚拟种群"这一层。
2. **丧尸个体 AI** `zombie.gd`：闲逛 / 调查 / 追击 / 前摇攻击 / 砸门窗 / 翻窗 / 硬直 / 尖啸，视觉（距离、视锥、射线、
   昼夜和手电影响）+ 听觉（按距离概率响应）+ 群体传染。寻路用的是 `AStarGrid2D`（0.5 米格），不是导航网格。
3. **生存数值** `survival.gd`：饥渴、疲劳、恐慌、体力、疼痛、伤口（抓伤 / 撕裂 / 咬伤，各有流血和感染概率）、
   感染进程、物品使用效果、状态标签。数值是拍的，没试玩过。
4. **物品表、武器数值、战利品表** `items.gd`：约 35 种物品、按容器种类的掉落权重。
5. **程序化建筑生成** `building.gd` + `town.gd`：房间切分、墙体开门窗洞、家具和容器摆放、整镇布局、任务物品保底投放。
   这是为低模风格写的，和现在"正式城镇"的做法可能不是一条路，用不用由接手的人判断。
6. **门窗** `door.gd`、`window_pane.gd`：开关、砸破、钉木板加固、丧尸破坏。
7. **气氛导演** `dread.gd`：环境音混合、心跳、远处枪声（同时把尸群引走）、雾边缘的人影幻觉。
   和主文档里"理智值 + 幻影"的设计方向一致，可以参考。

## 不建议复用的

- `shaders/post.gdshader`、240p 子视口方案、`project.godot` 的渲染设置（方向已变）。
- 贴图和模型大概率要重做（主文档已写明用户知情）。
- `player.gd`、`weapon_system.gd`：`fps/` 里已有**跑通并有自测**的版本，以那边为准。
  这边唯一多出来的是"翻窗 / 翻越薄障碍"的判定思路和触屏辅助瞄准，后者在 PC 方向下用不上。
