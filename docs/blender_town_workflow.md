# 小镇在 Blender 里重做：怎么拿出去、怎么拿回来

写于 2026-11-12。用户看过贴了图的灰盒后说："程序生成痕迹很重，后续还要在 Blender 大改。"
这份文档讲清楚灰盒怎么进 Blender、改完怎么回到游戏里、哪些尺寸不能动。

## 现状：什么验证过，什么没有

| 环节 | 状态 |
| --- | --- |
| 灰盒导出成 `.glb` | 能用。`art/town/blender/town_greybox.glb`，1.7 MB |
| 导入 Blender 存成 `.blend` | 能用。`art/town/blender/town_greybox.blend`，17 个地块各一个集合、146 个网格物体、48 个标记点。俯视预览图 `town_greybox_preview.jpg` 我看过，布局和朝向是对的 |
| 从 Blender 再导出、游戏里读回来 | **原样往返验证过一次**（没做任何修改）：48 个标记点位置分毫不差，146 个网格都生成了碰撞，15 种灰盒材质自动换成了贴图 |
| 游戏真的用 Blender 的模型跑起来 | **加油站一个地块做了**（见下一节"一栋一栋地换"）。其余 16 个地块仍然是代码搭的盒子 |
| 整个小镇换成一个大模型 | 没做。`--check-model` 只是能加载、能检查 |
| 手工改过的模型 | 没有。加油站的模型是脚本生成的，还没有人在 Blender 里手动改过它 |

## 一栋一栋地换（现在实际在用的做法）

第一栋是加油站和便利店（2026-11-12）。做法是：**外观用 Blender 的模型，碰撞仍然用灰盒的盒子。**
这样自测（玩家和怪走得通每个房间）不用重写，模型只要守住灰盒的占地就行。

| 文件 | 是什么 |
| --- | --- |
| `art/town/blender/lotkit.py` | 建模用的小工具库：盒子（可倒角）、圆柱、软管、拉伸轮廓、锥台、垃圾袋；按米自动铺 UV；按图片里的矩形贴招牌和包装 |
| `art/town/blender/build_gas_station.py` | 加油站的建模脚本。所有尺寸和 `town_layout.gd` 的 `_gas_station` 一一对应 |
| `art/town/blender/gas_station.blend` | 脚本生成的 Blender 文件。材质上接好了颜色贴图，打开就能看到大致效果 |
| `fps/assets/town/gas_station.glb` | 游戏读的模型（2 MB，不含贴图） |

```bash
# 重新生成（改了脚本之后）
blender --background --factory-startup --python art/town/blender/build_gas_station.py
godot --headless --path fps --import
# 只看灰盒（对比用）
godot --path fps res://world/town/town.tscn -- --greybox
```

**想手工改**：打开 `gas_station.blend` 直接改，然后导出 glTF 覆盖 `fps/assets/town/gas_station.glb`
（格式 `.glb`，+Y 向上，应用修改器，不带相机和灯，**图像选"无"**）。注意：再跑一次脚本会把手工改动冲掉。
所以要么以后只手工改，要么把改动写回脚本，两条路选一条。

这种模型的约定（在下面"三条约定"之上再加几条）：

- **坐标是地块自己的**，不是世界坐标：x 沿街，z 朝地块深处，原点在人行道内沿。模型在游戏里挂在地块节点下面。
  在 Blender 里看到的就是：X 沿街，−Y 朝地块深处，Z 向上。
- **只管外观的物体名字以 `-nocol` 结尾**。现在除了一个碰撞物体，全都是。
- **新增的实心东西**（防撞栏、冰柜、垃圾桶、报箱、椅子、托盘堆…）的碰撞放在 `props-colonly` 这个物体里，每样一个简单的盒子。
  灰盒里已经有的东西（墙、货架、冷柜、柜台、油泵、警车）不要再加，它们的碰撞是灰盒的盒子。
- **灯**：名字是 `light_<种类>_<序号>` 的空物体。模型里只要有一个这样的空物体，这个地块原来写在 `town_layout.gd` 里的灯就全部不用，改用模型里的。
  每种灯的亮度、颜色、范围、是否投影写在 `fps/world/town/town.gd` 的 `MODEL_LIGHTS` 表里。
  现在有的种类：`canopy`（朝下的聚光，投影）、`tube`、`bulb`、`door`、`wallpack`、`cooler`、`vending`、`neon`、`sign_green`、`sign_warm`、`sign_blue`。
- **招牌、包装这类"一张图"的材质**：`tools/install_texture.py <名字>` 现在认只有一张图的素材（`_Emission` 的会发光；`名字+glow` 让 `_Color` 的也发光）。
  图里只用一块的，在脚本里写矩形（左、上、右、下，0 到 1，和看图软件里的方向一样）。
- **同一套贴图的变体**（比如同一种墙刷成另一个颜色）：在 `fps/assets/materials/` 里手写一个 `.tres`，名字是 `原名_后缀`，
  引用同一套图、加上 `albedo_color`。现在还没有用到这种变体。
- 铁丝网是 `tools/make_chainlink.py` 画的（库里没有带镂空的），材质名 `ChainLink`。

在 `fps/world/town/town.gd` 的 `LOT_MODELS` 表里登记了的地块才会换。下一栋照这个样子加一行、写一个 `build_<地块>.py`。

## 整个小镇拿出去

```bash
# 1. 从游戏导出灰盒（纯色材质，材质名就是灰盒标签；每个标记点一个空物体）
godot --headless --path fps res://world/town/town.tscn -- --export-gltf=$PWD/art/town/blender/town_greybox.glb
# 2. 整理成 .blend，并出一张俯视预览图
blender --background --factory-startup --python art/town/blender/make_blend.py
```

`.blend` 里的东西：

- **每个地块一个集合**（`gas_station`、`miller`、`brick_row`、`clark`、`street` 等）。
- 物体名是 `地块__材质标签`，例如 `miller__brick`。同一地块同一种材质的所有盒子合成了一个物体。
- **`markers` 集合**：48 个空物体，名字是 `marker_<编号>`（`marker_police_car`、`marker_belt`、`marker_nest` …），就是设计稿里关键物品和事件的位置。
- 所有东西都在世界坐标里，没有父子关系。1 个单位 = 1 米。Blender 的 +Y 是北。

## 拿回来

在 Blender 里导出 glTF（`.glb`，+Y 向上，应用修改器，不带相机和灯），然后检查：

```bash
godot --headless --path fps res://world/town/town.tscn -- --check-model=<导出的 .glb 的完整路径>
```

它会报告网格、碰撞、标记点的数量，材质认出了几种，标记点有没有丢、有没有被挪动。读模型的代码在 `fps/world/town/town_model.gd`。

### 三条约定

**材质靠名字对。** 在 Blender 里给材质起名：

| 材质名 | 游戏里得到什么 |
| --- | --- |
| 和 `fps/assets/materials/` 里某个文件同名（如 `red_brick`、`Asphalt015`） | 那一套贴图，用模型自己的 UV。**重做过的部分用这种** |
| 灰盒标签（`brick`、`asphalt`、`siding`、`wall_in` …，见 `TownBuilder.TEXTURED`） | 该标签对应的那套贴图，按世界坐标投影，不看 UV。没动过的灰盒部分保持原样就行 |
| 其他名字 | 保留模型自带的材质 |

Blender 自动加的 `.001` 后缀会被忽略。要用库里还没装进游戏的贴图，先跑 `tools/install_texture.py <素材名>`。

**碰撞默认全有。** 每个网格都按它的三角面生成碰撞。物体名以 `-nocol` 结尾的不生成（草、电线、小摆件）；
以 `-colonly` 结尾的只当碰撞、不显示（给复杂模型配一个简单的碰撞体时用）。

**标记点不要删、不要改名。** 可以移动（房间布局变了就跟着挪），但 48 个都要在。游戏以后靠它们放物品、放怪、触发事件。
挪动了的标记点，检查命令会报"不在原位"，那是提醒不是错误，确认是有意挪的就行。

## 不能动的尺寸

这些是把灰盒调到"玩家和怪都走得通"的过程中试出来的。重做时外观随便改，这些数要守住，否则会出现走不过去、翻不上去、怪卡住。

| 项目 | 要求 | 原因 |
| --- | --- | --- |
| 门洞净宽 | 至少 1.0 米 | 0.9 米时寻路时通时不通（地块相对网格是斜的） |
| 门洞净高 | 至少 2.05 米 | 玩家身高 1.8 米 |
| 楼梯坡度 | 不超过 35 度 | 寻路上限 40 度，玩家上限 46 度，留余量 |
| 楼梯宽度 | 两侧有扶手或墙的至少 1.5 米；一侧敞开的至少 1.0 米 | 窄了寻路网格会断 |
| 楼梯扶手 | 楼梯侧面要有实心的挡板或扶手，但底端 0.7 米不要有 | 没有挡板，怪会从侧面切上楼梯卡住；挡板伸到底会堵住楼梯口 |
| 楼梯做法 | 看得见的踏步之外，要有一块连续的斜面碰撞（`-colonly`） | 一级一级的台阶碰撞会让玩家和怪颠簸、卡住 |
| 直接迈上去的高度 | 不超过 0.38 米（玩家）；怪是 0.2 米 | 路缘 0.15 米、门槛都在这个范围内 |
| 能翻越的高度 | 0.45 到 2.1 米；翻上去的落点上方要有 1.45 米净空 | 汽修行阁楼屋顶原来差 8 厘米，翻不上遮雨棚 |
| 窗台 | 0.9 米左右，窗洞净高至少 1.2 米 | 蹲着的玩家 1.1 米高，要钻得过去 |
| 地沟上方的车 | 车尾离台阶底端至少 1 米 | 太近的话下台阶会撞头，然后自动翻到车顶上 |
| 墙和地面 | 做成有厚度的实体，不要单面片 | 单面片从背面能穿过去 |
| 地沟、楼梯口 | 地面要真的开洞 | 不能只是在整块地面上放一个凹下去的模型 |

改完之后最好再跑一遍"每个房间都走得到"的检查。**现在的小镇自测只认代码搭的盒子，还不能对 Blender 的模型跑**，这是下一步要做的（见下）。

## 关于"程序生成痕迹"

灰盒看着假，主要是这几样，重做时值得优先处理：

- **所有东西都是直角方盒**。真实的房子有屋檐出挑、窗框和门框的凹凸、踢脚、雨水管、台阶的踏面出沿。加上这些轮廓，比换贴图有效得多。
- **没有不规则**。每栋房子都正对街道、间距均匀、屋顶一个样。把几栋转几度、前后错开、屋顶高低不同。
- **没有杂物**。设计稿要的"生活杂物密度"现在是零：电线、信箱、垃圾桶、空调外机、晾衣绳、路边停的车、院子里的东西。素材库里有 77 个现成模型（`textures/models/`）还没用。
- **地面是平的**。路面该有拱度和排水沟，人行道该有翘起的板，院子该有起伏。
- **贴图是整面平铺**。没有污渍、流痕、墙根的脏、路面标线。这要靠贴花，库里有，还没接。

## 还没做的

1. 其余 16 个地块（米勒五金汽修、砖楼一排、克拉克家、主街、民宅…）还是灰盒。
2. 模型的碰撞还是灰盒的盒子。哪天模型的形状和灰盒差得多了（比如斜屋顶、弧形墙），就得让模型自己带碰撞，
   那时小镇自测要改：寻路连通性那一项不依赖盒子，改动不大；"让玩家走进每个房间"那几项的目的地现在写的是地块里的坐标，要改成用标记点。
3. 整镇导出的灰盒（`town_greybox.blend`）里没有灯，也看不到贴图（纯色）。按地块做的模型两样都有了。
4. 贴花（污渍、流痕、油渍、路面标线）还没有接。加油站现在最缺的就是这个：地面和墙面太干净。
5. 警车只是个有形状的占位：没有涂装文字（MICHIWA STATE PATROL 217）、没有内饰、车灯不亮。
